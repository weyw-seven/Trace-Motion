# 固件模块边界

task2 循迹找球包加入后，仓库包含三个不同的机器人任务。下面的边界用于避免复制同名代码后各自漂移。

| 层级 | 轨迹绘图 | 红外循迹 | 相机循迹找球 | 当前处理 |
| --- | --- | --- | --- |
| 电机和底盘基础 | `motor_control`、`chassis_kinematics`、`chassis_odometry`、`chassis_motion` | 同名模块 | 同名模块 | 运动学、里程计可复用；其余为不同实现，暂留应用内 |
| 传感器 | MPU6050、超声、OLED | 红外、MPU6050、超声、OLED | UVC、MPU6050、超声、OLED、语音 | 驱动待接口统一后再抽取 |
| 轨迹与通信 | TRJ2、N3 service、runner | 无 | 无 | 绘图应用专用 |
| 路径输入 | PC 规划输入 | 四路红外模式 | UVC、JPEG 解码、黑线和彩球检测 | 各任务专用 |
| 任务行为 | 绘图、笔控制、轨迹跟踪 | 红外循迹、避障 | 视觉循迹、避障、找球、推球 | 各应用专用 |
| 调试与交互 | PC UI、串口/Wi-Fi N3 | OLED | Web/MJPEG、语音提示 | 各应用专用 |

## 抽取条件

一个模块只有同时满足以下条件，才可从应用移动到 `firmware/components/`：

1. 不包含任务状态机、目标坐标、专用阈值或硬编码 Wi-Fi 凭据。
2. 板级引脚、轮径、PID 和限幅参数通过配置传入。
3. 有稳定的公共头文件、独立 `.c` 实现、ESP-IDF 构建清单和最小测试。
4. 至少被两个应用以相同 API 使用。

在此之前，应用级副本优于“看似共享、实际耦合”的伪公共组件。
