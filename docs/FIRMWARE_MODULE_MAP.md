# 固件模块边界

固件按“公共组件 + 应用任务”组织。公共组件负责稳定的硬件和协议能力；应用目录只保留传感器输入、任务状态机和业务行为。

| 层级 | 公共组件 | 应用专用代码 |
| --- | --- | --- |
| 底盘 | `tm_chassis`：电机、MPU6050、运动学、里程计、运动控制 | 各任务的速度、距离和动作策略 |
| 传感器 | `tm_sensors`：红外、超声 | UVC 相机、语音、网页调试 |
| 红外任务 | `tm_line_ir`：红外循迹、避障、OLED 状态显示 | `line-infrared` 的应用入口 |
| 轨迹通信 | `tm_trajectory`、`tm_n3`：TRJ2、轨迹运行、N3 通信 | `trajectory-drawing` 的应用入口与 SPIFFS 资源 |
| 相机任务 | — | 视觉循迹、彩球检测、找球和推球 |

## 维护规则

1. 可被多个任务以相同 API 使用的硬件、协议和算法放在 `firmware/components/`。
2. 与某一传感器输入、任务顺序、网页界面或行为目标绑定的代码放在对应 `apps/` 目录。
3. 公共组件的实现宏只能在组件自身的 `.c` 文件中定义一次。
4. 修改引脚、轮径、PID 或限幅前，先确认影响的所有应用并完成台架测试。

相机循迹中的底层模块与红外任务的同名模块并非相同实现。在其接口、参数和硬件验证收敛前，不应以复制文件的方式替换公共组件。
